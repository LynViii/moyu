# 0.5.1 资源复查

日期：2026-11-12。比较 0.5.0 发布 EXE 与 0.5.1。没有修改系统计时器分辨率、电源计划、分辨率或缩放，没有用强制 GC/工作集裁剪伪装低内存。

## 方法

`tests/measure_resources.ps1` 启动独立 C# 测量进程，加载相应 EXE 的实际 UpdateForm，在主屏 2560×1440 显示。预热 1.5 秒后测约 8 秒，计实际 Paint 次数与进程 CPU 时间。内存为测量起止两次采样均值，不是峰值；仅起止读取进程内存，避免高频进程枚举污染 CPU。CPU 百分比按一个逻辑核心归一化，不是任务管理器总 CPU 百分比。此过程不创建真实伪装会话，因此不包含开始菜单轮询成本。

这不是严格受控实验：后台负载、CPU 调度与功耗状态会影响数据。早期全模式快路径出现收益不稳定，已撤回；最终只对 Win11 普通流畅模式启用局部缓冲/原生消息唤醒，Win10 和节能保留兼容路径。不声称所有模式都更省 CPU。

## Win11 默认流畅模式

| 指标 | 0.5.0 第一次 | 0.5.0 重复 | 0.5.1 最终 |
| --- | ---: | ---: | ---: |
| 观测秒数 | 8.0878 | 8.0880 | 8.0845 |
| CPU 时间 ms | 484.375 | 578.125 | 265.625 |
| 单逻辑核心 CPU % | 5.9890 | 7.1480 | 3.2856 |
| 实际 Paint FPS | 50.817 | 50.940 | 50.838 |
| 起止私有内存均值 MiB | 27.9785 | 28.0781 | 26.4707 |
| 起止工作集均值 MiB | 42.9805 | 43.3242 | 42.0918 |
| GDI 句柄 起/止 | 59/59 | 59/59 | 60/60 |

本机这组默认场景 CPU 时间下降约 45%–54%，私有内存均值下降约 5%–6%，实际绘制频率基本相同。优化版另外两次同一路径试测约 3.86% 和 4.06% 单核 CPU，说明仍有波动；不是通用性能保证，也不是恒定 60 FPS 保证。

## 其他模式与空闲

| 场景 | 0.5.0 两次单核 CPU % | 0.5.1 最终单核 CPU % | Paint FPS 旧/新 |
| --- | --- | ---: | --- |
| Win11 节能 | 1.3526 / 2.1252 | 0.7730 | 约 15.95 / 16.08 |
| Win10 普通 | 4.6373 / 6.3721 | 8.6927 | 约 50.67–51.57 / 50.07 |
| Win11 窗口隐藏 | 0 / 0 | 0 | 0 / 0 |

Win10 CPU 数据较高且波动大，没有证据证明该模式 CPU 改进；最终保留原有双缓冲和 BeginInvoke 路径，不把试验快路径推给所有模式。原始 JSON 随本地封存保存，不能只据默认模式数字推断全部场景。

此外 `tests/measure_idle.ps1` 从外部测量真实 `--silent` 托盘进程：约 10.017 秒内观测 CPU 时间 0ms，私有内存 25.42 MiB、工作集 41.27 MiB，没有可见主窗口。0ms 受系统计时精度与短采样窗口限制，不代表永远零开销。

## 正确性保护

- 局部帧与完整帧 RGB 逐像素一致；静态文字/背景不被转圈刷新覆盖，验证 Win10/Win11 与黑/浅色组合。
- 尺寸变化释放旧缓存；40 次创建、绘制、释放没有 GDI 句柄增长。
- 保持真实时间驱动动画、隐藏/最小化暂停、最多一个待处理请求；默认速度与节能开关不变。
- 原生消息窗口只接收自身帧消息，不安装全局键盘钩子。定时器和消息窗口随视图释放。

实现参考微软 [手动管理图形缓冲](https://learn.microsoft.com/en-us/dotnet/desktop/winforms/advanced/how-to-manually-manage-buffered-graphics) 与 [BufferedGraphics.Render](https://learn.microsoft.com/en-us/dotnet/api/system.drawing.bufferedgraphics.render?view=netframework-4.8.1)，没有引入第三方运行时。
